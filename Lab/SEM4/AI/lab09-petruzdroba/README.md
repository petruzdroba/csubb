## Parameter influence

### What each parameter does
- do_sample: whether the model picks the most probable token (*word*) -> deterministic, or whether it sample from the probability distribution
- max_new_tokens: how many tokens is the model allowed to generate, *token -> a word or a part of a word*
- num_beams: (*only matters when do_sample is False=deterministic*), instead of tracking one seq. it tracks N seq. at the same time and keeps the best oe
- temperature: (*for do_sample=True*), above 1.0 - the model is more chaotic but more creative, below 1.0 is more confident but repetitive
- top_p: (*do_sample=True*) cuts all token with prob. under a threshold
- top_k: keeps the k most probable tokens
- repetition_penalty: penalises the tokens already in the output, fixes looping

# Task B

## Why the Gutenberg Dataset is shit

The Gutenberg poetry dataset used in this training contains a lot of non-poetic noise such as metadata, headers, and digitization artifacts. In this experiment, that directly caused the model to generate garbage text like “Advertisements” and repeated names such as “Hiawatha.” Because the model learns statistical patterns, it treats these artifacts as valid continuations alongside real poetry. This leads to overfitting on frequent junk patterns instead of learning consistent poetic style. As a result, output quality is heavily degraded despite fine-tuning.

## Poem Sentiment

The new model performs better because the training data was cleaned to remove metadata, repetitive boilerplate, and non-poetic text, which previously caused looping and irrelevant outputs. With a more focused poetry dataset and stronger decoding constraints (repetition penalty and n-gram blocking), the model generates more coherent and context-relevant continuations. Compared to the previous version, it produces fewer artifacts and less repetition, and it follows the input prompt more consistently. However, it still occasionally drifts into generic narrative language due to the limitations of the base GPT-2 model.
